# 모델 오케스트레이션 규칙

1화를 아홉 번 고치며 굳은 분업이다. 단계마다 맞는 모델을 쓰고, 기획한 모델의 결과를 만드는 모델이 멋대로 바꾸지 않는다. 품질은 이 분업에서 나온다.

## 단계별 담당

| 단계 | 담당 | 이유와 주의 |
|---|---|---|
| 조사 | 가벼운 모델(Haiku 등) 서브에이전트, 여러 갈래 동시 | 먼저 `references/` 조사 저장소를 읽고 빈 곳만 조사한다. 결과는 같은 형식으로 저장소에 더한다 |
| 세계관·대본·연출 기획 | 가장 좋은 추론 모델(Claude Fable, 없으면 Opus) **한 개만** | 대본·컷 표·모션 기획은 이 모델이 쓴다. 제작 모델이 직접 대본을 쓰면 엉뚱한 설정이 끼어들었다(1~3판 기각) |
| 대본 외부 검토 | 다른 회사 모델(Codex·ChatGPT) | 같은 모델끼리는 같은 맹점을 공유한다. 「동기·인과」, 「시트콤식 재미」, 「스토리텔링」을 따로 물으면 효과가 컸다 |
| 교육 메시지 점검 | 기획 모델 | 「60대 당뇨 환자가 보고 무엇을 기억하나」로 본다. 재미가 늘수록 메시지가 옅어진다 |
| 대사·화면 문구 점검 | 기획 모델 + 사람이 소리 내 읽기 | 번역투(「제가요!」 같은 말)를 거른다. 사람이 마지막에 읽는다 |
| 그림(배우·소품·무대) | Codex image_gen(Images 2.6), **기준 그림 편집 방식** | 새로 그리지 말고 승인된 그림을 고친다. 소품 크기는 재기 → 줄이기를 2~4번 |
| 음악·효과음 | Suno, **정식 테마를 reference로만** | 새 테마 금지(`rules/music.md`) |
| 조립·코드·렌더·검사 | 제작 모델(Claude Opus 등) | 기획서대로만 만든다. 바꿔야 하면 바꾸지 말고 이유를 보고한다 |
| 승인·검수 | 사람 | 그림 승인 모음, 대사 소리 내 읽기, 의료진 검수, 환자 패널 |

## 순서

1. 조사(빈 곳만) → 2. 기획 모델이 대본 → 3. 외부 모델 검토(동기·재미·메시지) → 4. 기획 모델이 반영 → 5. 사람이 대사 읽기 → 6. 제작 모델이 그림·조립·렌더 → 7. 자동 검사 + 사람이 영상 확인 → 8. 의료진 검수

3~4는 한 번에 끝나지 않는다. 1화는 외부 검토를 다섯 번 받았다.

## 지킬 것

- 기획 모델은 동시에 하나만 돌린다(비용·일관성).
- 서브에이전트에게는 읽을 파일 경로와 지금까지의 사람 지적을 **전부** 넘긴다. 지적 일부만 넘기면 같은 실수가 돌아온다.
- 제작 모델의 보고에 「기획과 다르게 한 것」이 있으면 사람이 확인한다.
- 소리는 수치로만 맞추지 말고 사람이 들어 본다(모델은 듣지 못한다).

## 계정별로 쓰는 모델

| 계정 | 기획 | 제작 | 그림 |
|---|---|---|---|
| Claude 구독 | Fable(없으면 Opus) | Opus | Codex 내장 그림 |
| Bedrock | 열려 있는 가장 좋은 Claude(보통 Opus) | Opus 또는 Sonnet | Codex 또는 OpenAI API |
| Claude API 키 | Fable(없으면 Opus) | Opus | Codex 또는 OpenAI API |
| Codex만(ChatGPT·OpenAI) | 가장 좋은 GPT 추론 모델 | 같은 모델 | Codex 내장 그림 또는 OpenAI API |

어느 계정이든 대본 외부 검토는 **다른 회사 모델**에게 받습니다. Claude로 기획했으면 GPT에게, GPT로 기획했으면 Claude에게 묻습니다. 설정은 `docs/providers.md`.
